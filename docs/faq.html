Häufig gestellte Fragen (FAQ)

Welche XJustiz-Nachrichten unterstützt der eNoVA-Editor?

Der eNoVA-Editor unterstützt ausschließlich das Format eNoVA.2900003. Er verarbeitet eingehende Nachrichten vom Typ ersuchenSachentscheidung und erstellt daraus Antwortnachrichten vom Typ sachentscheidung.

Welche Bescheide können mit dem eNoVA-Editor erstellt werden?

Der eNoVA-Editor deckt eNoVA.2900003 vollständig ab. Die möglichen Fragen sind auf der Seite:
https://www.xrepository.de/details/urn:xoev-de:xjustiz:codeliste:enova.ersuchensachentscheidung
aufgelistet.

Die Behörde kann auf diese mit folgenden Antworten reagieren:
https://www.xrepository.de/details/urn:xoev-de:xjustiz:codeliste:enova.sachentscheidung

Welche Antworten auf welche Fragen möglich sind, steht in der Datei:
https://github.com/it-at-m/eNoVa-Editor/blob/main/decision-config.xml
Diese Liste ist mit der Bundesnotarkammer abgestimmt.

Kann eine Behörde selbst eine Anfrage an einen Notar erstellen?

Nein. Beim Format eNoVA.2900003 wird die Kommunikation immer durch eine Anfrage des Notars eingeleitet. Die Behörde kann darauf mit einer Sachentscheidung antworten, aber keine eigene initiale Anfrage erstellen.

Muss die Antwort der Behörde als PDF erstellt werden?

Nein. Die XML-Datei selbst stellt den Bescheid dar. Ein zusätzliches PDF ist bei eNoVA.2900003 nicht vorgesehen. Die XML-Antwort muss entsprechend signiert werden.

Wie muss die Antwort der Behörde signiert werden?

Die Antwort benötigt eine Signatur mit Organisationsvalidierung. Dadurch kann die empfangende Stelle überprüfen, ob der Bescheid tatsächlich von der zuständigen Behörde stammt. Eine gewöhnliche persönliche Signatur oder ein Siegel reicht dafür nicht aus.

Kann es passieren, dass eine Signatur beim Versand ungültig wird?

In einem Testszenario konnte derartiges produziert werden. Bereits Änderungen an den Zeilenumbrüchen einer XML-Datei können eine binäre Signatur ungültig machen. Windows verwendet üblicherweise CR+LF, Linux dagegen LF. Eine solche Änderung konnte bei einem Test bei der Übertragung über die beBPo-Infrastruktur erzeugt werden. Deswegen hat der eNoVA-Editor eine Option, innerhalb der XML-Antwort keine Zeilenumbrüche zu verwenden.

Was braucht man alles, um 'eNoVA-ready' zu sein?

  • Ein besonderes elektronisches Behördenpostfach (beBPo).
  • Ein Tool oder eine Fachanwendung, die eNoVA.2900003 lesen, anzeigen und schreiben kann, beispielsweise den eNoVA-Editor.
  • Eine Signatur mit Organistaionsvalidierung. Die meisten Signaturen, die vor Mitte 2026 ausgestellt wurden, haben keine Angabe, zu welcher Gemeinde die ausstellende Person gehört. Diese müssen entsprechend ersetzt werden.
  • Eine Signatursoftware, die CAdES (detached) erstellen kann. Der Hersteller der Signatursoftware kann Auskunft geben, ob die Software den Anforderungen des eNoVA-Gesetzes gerecht wird. Die Signatur-Software stellt möglicherweise weitere Anforderungen.

Welche Hardware- und Software-Anforderungen stellt der eNoVA-Editor?

Der eNoVA-Editor ist eine Java-Desktopanwendung. Prinzipiell ist er damit auf jedem Betriebssystem lauffähig. Derzeit wird nur MS Windows unterszützt. Weitere Betriebssysteme auf Anfrage.
Weiteres siehe https://github.com/it-at-m/eNoVa-Editor/issues/38.

Wie kann ich die Anzeige des eNoVA-Editors unter Windows vergrößern?

Drücken Sie die "Windows-Taste" und gleichzeitig die "Plus-Taste". Geben Sie die gewünschte Vergrößerung in Prozent ein. Schließen Sie das Fenster anschließend und fahren Sie mit der Bearbeitung fort.

Welche Alternativen gibt es zum eNoVA-Editor?

Als kostenlose Option stehen die XJustiz-Werkzeuge zur Verfügung:
https://xjustiz-werkzeuge-3b2324.usercontent.opencode.de/anwendungsfaelle/enova/

Darüberhinaus gibt es mehrere kostenpflichtige Alternativen von kommerziellen Anbietern.

Welche Technologien werden im eNoVA-Editor verwendet?

Der eNoVA-Editor ist eine Java-Desktopanwendung auf Basis von Java 21 und JavaFX 21. Zur Verarbeitung von XJustiz-Nachrichten werden XML, XPath und XSLT (Saxon-HE) eingesetzt. Als Build-Werkzeug dient Apache Maven.
