eNoVA-Editor

Der eNoVA-Editor ermöglicht Kommunen, Dateien im Format XJustiz.enova.2900003 in einer menschenlesbaren Form anzuzeigen und eine XJustiz-Antwortdatei zu erstellen.

Quellcode auf GitHub Installationsanleitung Dokumentation des Formats
Ab Januar 2027 sind Kommunen in Deutschland verpflichtet, Vorkaufsrechtsanfragen von Notaren digital im Format XJustiz.enova.2900003 zu bearbeiten.

Über das Projekt

Die Landeshauptstadt München entwickelt federführend den eNoVA-Editor für alle Kommunen in Deutschland. Sie stellt das Tool als Open-Source-Software kostenlos unter der MIT-Lizenz zur Verfügung.

Das Projekt befindet sich derzeit in der Testphase. Diese wird voraussichtlich am 1. Dezember 2026 abgeschlossen.

Was macht der eNoVA-Editor?

Nach Eingang einer Nachricht über das beBPo öffnen Sachbearbeiter*innen die XML-Datei im Editor. Die für die Bearbeitung relevanten Inhalte werden übersichtlich dargestellt.

Anschließend können sie Aktenzeichen, Sachbearbeiter*in und Entscheidung erfassen und daraus eine rechtskonforme XJustiz-Antwortdatei erstellen.

Häufig gestellte Fragen (FAQ)

Welche XJustiz-Nachrichten unterstützt der eNoVA-Editor?

Der eNoVA-Editor unterstützt ausschließlich das Format eNoVA.2900003. Er verarbeitet eingehende Nachrichten vom Typ ersuchenSachentscheidung und erstellt daraus Antwortnachrichten vom Typ sachentscheidung.

Kann eine Behörde selbst eine Anfrage an einen Notar erstellen?

Nein. Beim Format eNoVA.2900003 wird die Kommunikation immer durch eine Anfrage des Notars eingeleitet. Die Behörde kann darauf mit einer Sachentscheidung antworten, aber keine eigene initiale Anfrage erstellen.

Muss die Antwort der Behörde als PDF erstellt werden?

Nein. Die XML-Datei selbst stellt den Bescheid dar. Ein zusätzliches PDF ist bei eNoVA.2900003 nicht vrogesehen. Die XML-Antwort muss entsprechend signiert werden.

Wie muss die Antwort der Behörde signiert werden?

Die Antwort benötigt eine Signatur mit Organisationsvalidierung. Dadurch kann die empfangende Stelle überprüfen, ob der Bescheid tatsächlich von der zuständigen Behörde stammt. Eine gewöhnliche persönliche Signatur oder ein Sigel reicht dafür nicht aus.

Kann es passieren, dass eine Signatur beim Versand ungültig wird?

In einem Testszenrio konnte derartiges produziert werden. Bereits Änderungen an den Zeilenumbrüchen einer XML-Datei können eine binäre Signatur ungültig machen. Windows verwendet üblicherweise CR+LF, Linux dagegen LF. Eine solche Änderung konnte bei einem Test bei der Übertragung über die beBPo-Infrastruktur erzeugt werden. Deswegen hat der eNoVA-Editor eine Option, innerhalb der XML-Antwort keine Zeilenumbrüche zu verwenden.

eNoVA Editor

The eNoVA Editor enables German municipalities to display XJustiz.enova.2900003 files in a human-readable format and create an XJustiz response file.

Source code on GitHub Installation Format documentation
Starting in January 2027, municipalities in Germany are required to process pre-emption right requests from notaries digitally in the XJustiz.enova.2900003 format.

About the project

The City of Munich is leading the development of the eNoVA Editor for municipalities throughout Germany. The tool is made available free of charge as open-source software under the MIT License.

The project is currently in the testing phase, which is expected to be completed by 1 December 2026.

What does the eNoVA Editor do?

After receiving a message via the beBPo secure government mailbox, caseworkers open the XML file in the editor. The information relevant to processing the request is displayed in a clear, structured format.

They can then enter the file reference, select the responsible caseworker and record a decision to generate a legally compliant XJustiz response file.

Frequently Asked Questions (FAQ)

Which XJustiz messages does the eNoVA Editor support?

The eNoVA Editor exclusively supports the eNoVA.2900003 format. It processes incoming ersuchenSachentscheidung messages and generates corresponding sachentscheidung response messages.

Can an authority initiate a request to a notary?

No. With eNoVA.2900003, communication is always initiated by a request from the notary. The authority can respond with a decision but cannot initiate its own request in this format.

Does the authority need to create a PDF response?

No. The XML file itself constitutes the official decision. An additional PDF is not required for eNoVA.2900003. The XML response must be signed accordingly.

How must the authority's response be signed?

The response requires a signature with organisational validation. This allows the receiving party to verify that the decision was issued by the responsible authority. An ordinary personal signature is not sufficient.

Why can a signature become invalid during transmission?

Even changes to line endings in an XML file can invalidate a binary signature. Windows typically uses CR+LF, while Linux uses LF. Such changes may occur during transmission via the beBPo infrastructure.
