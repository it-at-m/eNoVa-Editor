Installation Guide

This guide is intended for administrators who want to deploy the eNoVa Editor for their municipality or organization.

1. Download the eNoVa Editor

Download the current version of the eNoVa Editor from the GitHub Releases page.

Go to GitHub Releases

Download the file eNoVa-editor-<Version>.zip.

2. Installation

Extract the ZIP file to the desired installation directory.

Do not change the directory structure. 

eNoVa-editor/
├── app/
├── codelists/
├── Input.htm
├── Output.htm
├── sender-config.xml
├── caseworkers.xml
├── codelists.properties
├── answer-transform.xsl
└── eNoVa-editor.cmd

A separate Java installation is not required. The required Java runtime is included in the eNoVa Editor package.

3. Configure the sender

Open the file sender-config.xml.

Enter the name of your municipality or authority.

Example: 

<sender>
    <name>Municipality of Exampletown</name>
</sender>

The eNoVa Editor uses this name, among other things, when generating the XJustiz response.

4. Configure caseworkers

The caseworkers available for selection in the eNoVa Editor are configured in the file caseworkers.xml.

The example data included with the application must be replaced with the data of your own organization.

The configured entries are loaded when the application starts and are then available in the caseworker selection field.

5. Customizable files

The following files may be customized if required:

  • Input.htm – defines the HTML representation of the incoming XJustiz message.
  • Output.htm – defines the HTML representation of the generated XJustiz response.

Changes to these files affect the representation in the browser. They do not directly define the generated XJustiz response XML.

6. Technical files

The following files and directories are part of the technical configuration or application logic and should normally not be modified.

app/

Contains the application, its required libraries and the bundled Java runtime.

Files in this directory should not be manually modified, moved or deleted.

codelists/

Contains the XML files for the XJustiz codelists used by the eNoVa Editor.

Usage: Codelists translate technical codes into human-readable descriptions or provide the permitted values for selection fields.

For example, the values shown in the “Decision” selection field are loaded from a codelist in this directory.

Codelists are also used when displaying XJustiz messages. Technical codes, such as role or telecommunication types, can be resolved to their corresponding descriptions.

Configuration: The file codelists.properties defines which specific codelist file is used for a particular purpose.

Files in this directory should not be replaced or modified individually without checking that the codelist version and configuration still match.

codelists.properties

This file maps the codelist names used by the eNoVa Editor to the corresponding XML files in the codelists/ directory.

Example: sachentscheidung.file specifies which ENOVA.Sachentscheidung-*.xml file is used for the “Decision” selection field.

The file also describes the technical structure of the codelist XML files. For example, it specifies which column contains the technical code and which column contains the human-readable description.

Simplified process: 

codelists.properties
        ↓
defines the codelist file to use
        ↓
codelists/*.xml
        ↓
technical code → human-readable description

Changes to codelists.properties may cause a different codelist version or an incompatible file to be used. Changes should therefore only be made intentionally.

answer-transform.xsl

This file contains the XSLT transformation used to generate the XJustiz response.

Usage: When a response is generated, the eNoVa Editor passes the previously loaded XJustiz XML together with the data entered in the application to this XSLT file.

This currently includes, among other things:

  • file number
  • selected decision
  • selected caseworker
  • newly generated message ID
  • eNoVa Editor manufacturer information

The XSLT file then defines where these values are used in the generated XJustiz response and which parts of the original message are retained or modified.

Simplified process: 

incoming XJustiz XML
        +
user input
        ↓
answer-transform.xsl
        ↓
XJustiz response XML

Changes directly affect the generated XJustiz response. Incorrect changes may result in incorrect content or a response that no longer conforms to the expected XJustiz format. Changes should therefore only be made by persons with the appropriate XSLT and XJustiz knowledge and should be tested afterwards.

eNoVa-editor.cmd

Starts the eNoVa Editor on Windows.

When started, the file sets the installation directory as the application directory and then starts the bundled Java runtime from the app/ directory.

This file should normally not be modified.

7. Permissions

The eNoVa Editor creates the HTML views and response files in the same directory as the opened XML file.

Write access to the installation directory is not required for normal use. Write access is only required there when configuration files such as sender-config.xml, caseworkers.xml, Input.htm or Output.htm need to be changed administratively.

8. Start the application

Start the eNoVa Editor using: 

eNoVa-editor.cmd

After startup, an XJustiz XML file can be opened and processed using the application.
